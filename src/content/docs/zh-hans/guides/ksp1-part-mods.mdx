<Aside type="caution" title="实验性功能">
“莎士比亚计划”是一个用于在运行时导入KSP1部件模组的工具。它适合用来测试和游玩受支持的部件，但它并不是完整的KSP1兼容层。Redux不会运行KSP1的插件DLL。
</Aside>

## 安装位置

在玩家安装环境中，Redux会在以下位置查找KSP1导入内容：

```text
<KSP2 Redux安装目录>/mods/KSP1/
```

如果`KSP1`文件夹尚不存在，请创建它。

请将`mods/KSP1`视为等同于KSP1的`GameData`文件夹。把原本应放在`GameData`内的那些文件夹直接放到`mods/KSP1`中。例如：

```text
mods/
  KSP1/
    TundraExploration/
      Parts/
      Patches/
      ...
    KerbalReusabilityExpansion/
      Parts/
      ...
```

如果某个模组压缩包中有一个名为`GameData`的文件夹，请将该`GameData`文件夹的内容复制到`mods/KSP1`中，而不是复制外层的`GameData`文件夹本身。

比如这样的压缩包结构：

```text
GameData/
  SomePartMod/
  SomeAssetDependency/
```

应该变成：

```text
mods/
  KSP1/
    SomePartMod/
    SomeAssetDependency/
```

不是：

```text
mods/
  KSP1/
    GameData/
      SomePartMod/
```

## 基本步骤

1. 关闭Redux。
2. 打开Redux的安装文件夹。
3. 如果`mods/KSP1`尚不存在，请创建它。
4. 将KSP1部件模组中相对于GameData的部件文件夹和资源文件夹解压到`mods/KSP1`中。
5. 启动Redux并加载一个战役或存档。

导入器会在加载战役时运行，此时Redux已解析完资源和部件数据。如果你在游戏运行期间添加或移除了KSP1部件文件，请重启游戏，以确保导入结果正常。

## 依赖项

复制提供部件模组所引用的部件配置、模型、纹理、资源或其他资源的依赖项。

不要仅仅因为KSP1模组将其列为依赖项就复制KSP1的代码插件依赖。KSP2
Redux无法加载KSP1的插件DLL，因此那些仅为提供KSP1代码而存在的文件夹（例如`DeployableEngines`、`B9PartSwitch`、`ModuleManager`、`SmokeScreen`、`Waterfall`或类似的插件库），即使放入`mods/KSP1`，也不会成为可用的Redux插件。

Redux在导入器端对若干常见的KSP1库和模块模式做了处理，因此这些插件依赖通常不需要你单独安装：

- ModuleManager风格的配置补丁已在导入器内部实现。
- 对于`B9PartSwitch`、`CommunityResourcePack`和`Waterfall`的导入器别名，`:NEEDS`检查会被视为已满足。
- B9 Part Switch数据会被用于燃料箱定义、视觉变体、纹理切换以及禁用的变换。
- 如果可能，Waterfall模板元数据会被映射到Redux/KSP2的尾焰放置位置。
- 在可能的情况下，引擎尾焰的放置位置会读取SmokeScreen和RealPlume风格的引擎尾焰配置节点。
- 在可能的情况下，Animated Decouplers风格的模块会被映射到Redux的导入式分离器运行时。
- 导入器可识别Tundra的分离器和引擎切换模块。

## Redux会读取哪些内容

Redux会扫描KSP1的`.cfg`文件，并从最终确定的配置数据库中导入`PART`节点。兼容ModuleManager风格的补丁可以在这一确定阶段应用，因此诸如`Patches`和`Compatibility`之类的补丁文件夹也属于导入路径的一部分。

导入器目前只支持有限的一组KSP1部件模块，包括引擎、万向节、RCS、动量轮、指令舱、分离器、对接口、发电机、太阳能板、发射器、降落伞、资源进气道、升力/控制面、灯光、货舱、若干常见的切换器模块，以及尾焰导入器所用的Waterfall元数据。不支持的模块会被跳过，并在日志中给出警告。

纹理查找支持使用`.dds`、`.mbm`、`.png`、`.jpg`、`.jpeg`和`.tga`文件引用的KSP1纹理。

## 不应期待的内容

- 这是一个部件导入器，而不是通用的KSP1模组加载器。
- `Plugins`文件夹中的KSP1插件DLL不会作为Redux插件被加载。
- KSP1插件依赖文件夹通常用处不大，除非它们还包含导入部件所需的部件配置、资源配置、模型、纹理或其他资源。
- 内部空间、道具、声音以及其他KSP1系统，并不会仅仅因为文件存在就被导入成可用的KSP2系统。
- 仅限舱内活动（IVA）的功能、在KSP1插件中实现的自定义PartModule行为、自定义UI、自定义飞行逻辑、自定义科学系统以及自定义玩法系统都不会自动生效。
- 兼容性是逐个部件来判定的。同一个模组中，有些部件可能导入得很顺利，而另一些部件则可能不完整或无法使用。
- 如果某些部件依赖于不受支持的模块或自定义的KSP1插件代码，那么在加载时可能会出现行为缺失、外观异常或没有实用功能的情况。

如果某个模组依赖于另一个KSP1资源文件夹，请把该依赖项中相对于GameData的文件夹也放入`mods/KSP1`。如果它依赖某个KSP1代码插件来实现导入器无法模拟的行为，那么这么模组就需要另外专门移植到Redux/KSP2上。
